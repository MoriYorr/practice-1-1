# Задание 1. Разбор tsconfig.json

Откройте `tsconfig.json` в корне проекта и для каждой строки напишите
**своими словами**, что она делает. Не копируйте документацию —
объясните так, как будто рассказываете одногруппнику.

## compilerOptions
> Здесь находятся настройки, которые управляют тем, как TypeScript проверяет и компилирует код.

### target
> Определяет версию JavaScript, в которую TypeScript преобразует исходный код. В этом проекте используется `ES2020`, поэтому современные возможности языка сохраняются, если они поддерживаются этим стандартом.

### module
> Указывает формат модулей в скомпилированном коде. Значение `ESNext` оставляет современные конструкции `import` и `export`, чтобы дальше их мог обработать сборщик или среда выполнения.

### moduleResolution
> Определяет, как TypeScript ищет файлы и пакеты, указанные в `import`. Значение `bundler` рассчитано на проекты со сборщиком и позволяет разрешать импорты так, как это обычно делают современные сборщики.

### strict
> Включает сразу весь набор строгих проверок типов. Если указано `false`, отдельные строгие проверки всё равно можно включать по одной другими настройками.

### strictNullChecks
> Если включить эту настройку, `null` и `undefined` будут отдельными типами. Их нельзя будет передать или присвоить там, где ожидается, например, обычная строка или число.

### noImplicitThis
> Проверяет использование `this`. Если TypeScript не может понять, к какому объекту относится `this`, он сообщит об ошибке вместо того, чтобы молча считать его типом `any`.

### noImplicitAny
> Запрещает TypeScript автоматически назначать тип `any`, когда тип значения определить не получилось. В таких местах разработчику придётся явно указать подходящий тип.

### noImplicitReturns
> Проверяет, что функция возвращает значение во всех возможных ветках выполнения. Например, нельзя вернуть результат только внутри `if`, забыв про случай, когда условие ложно.

### esModuleInterop
> Упрощает импорт библиотек, использующих CommonJS, в код с ES-модулями. Благодаря этой настройке такие пакеты чаще можно подключать привычным импортом по умолчанию.

### skipLibCheck
> Пропускает проверку файлов типов библиотек (`.d.ts`) из зависимостей. Это ускоряет проверку проекта и не позволяет ошибкам внутри чужих описаний типов мешать сборке, но собственный код всё равно проверяется.

### forceConsistentCasingInFileNames
> Следит, чтобы регистр букв в путях импорта совпадал с настоящими именами файлов. Например, нельзя импортировать `User.ts` как `user.ts`, даже если текущая операционная система это допускает.

### outDir
> Задаёт папку, куда TypeScript складывает скомпилированные JavaScript-файлы. В этом проекте результат должен попадать в `./dist`.

### rootDir
> Указывает корневую папку исходных файлов и помогает сохранить их структуру при компиляции. Значение `.` означает корень всего проекта.

## include
> Перечисляет файлы, которые TypeScript должен включить в проект. Здесь проверяются все файлы внутри папок `src` и `tests`, включая их вложенные папки.

## exclude
> Перечисляет папки, которые TypeScript не должен добавлять в проект. Здесь исключены установленные зависимости `node_modules` и результат компиляции `dist`.

# Задание 1.2. Включение флагов

Для каждого пункта ниже:
1. Определите, какой флаг нужно поменять в `tsconfig.json`.
2. Внесите изменение.
3. Запустите `npm run check`.
4. Запишите результат в `task1.md`.

---

### 1. Строгие проверки типов
Включите опцию, которая делает `null` и `undefined` отдельными типами,
а не «совместимыми со всем». Без неё код с `null` компилируется, с ней — нет.

**Ваш ответ:** `strictNullChecks: true`

> Эта настройка запрещает использовать `null` и `undefined` там, где они явно не указаны в типе. Если значение может отсутствовать, это нужно отметить, например: `string | null`.

---

### 2. Проверка `this`
Включите опцию, которая ругается, если внутри функции используется `this`,
но функция не является методом класса (то есть `this` не определён).

**Ваш ответ:** `noImplicitThis: true`

> Эта настройка сообщает об ошибке, когда TypeScript не может определить тип `this`. Она помогает заметить обычную функцию, в которой `this` используется без понятного контекста.

---

### 3. Неявный `any`
Включите опцию, которая ругается, если переменная получает тип `any`
автоматически (например, функция без аннотаций параметров).

**Ваш ответ:** `noImplicitAny: true`

> Эта настройка требует явно указывать тип в тех местах, где TypeScript не смог вывести его самостоятельно. Так в коде не появляются незаметные значения типа `any`, для которых почти нет проверки типов.

---

### 4. Возврат из функции
Включите опцию, которая требует, чтобы **все** ветки функции возвращали значение,
если функция объявлена как возвращающая не-`void`.

**Ваш ответ:** `noImplicitReturns: true`

> Эта настройка проверяет каждый возможный путь выполнения функции. Если хотя бы в одной ветке нет `return`, TypeScript предупредит, что функция иногда возвращает значение, а иногда — `undefined`.
